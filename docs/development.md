# Development guide

## Configuration

`make setup` creates backend/.env once using random local values and restrictive
file permissions. It never replaces an existing file. The application reads that
file relative to backend/; environment variables take precedence.

| Setting | Purpose |
| --- | --- |
| DATABASE_URL | Host API/migration connection; PostgreSQL uses postgresql+psycopg:// |
| POSTGRES_PASSWORD | Local Compose database password, also used in its internal API URL |
| SECRET_KEY | JWT signing key, minimum 32 characters |
| ACCESS_TOKEN_EXPIRE_MINUTES | Positive token lifetime; default 60 |
| API_PORT / DB_PORT | Optional host port overrides for Compose |
| COMPOSE_PROJECT_NAME | Separate containers/volumes for an independent stack |

Compose builds its internal DATABASE_URL using the db service hostname. The host
DATABASE_URL uses localhost. If DB_PORT changes, update the host DATABASE_URL too
before running make migrate or a host API. A separate worktree does not isolate ports.

The current Compose file supplies DATABASE_URL and SECRET_KEY to containers; a
custom ACCESS_TOKEN_EXPIRE_MINUTES value in the host .env only affects host execution
unless it is explicitly added to the container environment.

Keep the same POSTGRES_PASSWORD when reusing an existing PostgreSQL volume. Changing
the file does not rotate the database user's password. Do not delete the volume
as a troubleshooting shortcut when it contains data you need.

## Run and inspect the stack

From the root:

```sh
make dev
docker compose --env-file backend/.env ps
docker compose --env-file backend/.env logs --tail=100 api migrate
```

For API reloads, follow the host workflow in the README. The container workflow
requires a rebuild after code changes. `make down` preserves the database volume.
Generated credentials should not be pasted into issues or command output.

## Database work

```sh
make migrate
cd backend
uv run alembic current
uv run alembic check
uv run alembic revision --autogenerate -m "describe the schema change"
```

Review autogenerated migrations before committing; generation is not proof of
correctness. Use a new revision for every schema change. Migration 0002 requires an
online connection to validate legacy prices, and blocks writes to products while
PostgreSQL converts them. Plan for that lock when applying it to a populated system.

Before adopting an existing unversioned database, back it up and compare its schema.
Do not blindly stamp a revision or drop tables. Test restoration before relying on
a backup. CI exercises downgrades only on disposable databases; production rollback
must account for lost columns, changed formats, and application compatibility.

The default tests use in-memory SQLite plus temporary migration files. The
TEST_DATABASE_URL and TEST_MIGRATION_DATABASE_URL overrides are for two distinct,
disposable PostgreSQL databases. The test suite creates/drops tables and downgrades
schemas; these variables must never point to a development database you want to keep.

## Dependency work

From backend/:

```sh
uv add PACKAGE
uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file requirements.txt
```

Use `uv add --dev PACKAGE` for tooling. Commit pyproject.toml, uv.lock, and any
changed export together. From the root, run make requirements-check and make audit,
then the normal tests. Dependabot PRs may need the export regenerated before CI passes.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Cannot connect to Docker | Start the Docker engine; docker info must succeed |
| Port already allocated | Stop the other stack or assign API_PORT/DB_PORT and a project name |
| Database authentication fails after editing .env | Existing volumes retain their original database password |
| Migration says a product needs correction | Inspect the named legacy row; fix invalid values deliberately and retry |
| Migration fails because tables already exist | Compare an unversioned database to the baseline; do not blindly stamp |
| Startup rejects SECRET_KEY | Use a random signing key of at least 32 characters |
| Product write returns 401 | Supply a valid bearer token for an active account |
| Product write returns 403 | The account is not an admin; no public promotion route exists |
| Product write returns 422 | Check GBP currency, decimal precision, bounds, nulls, and unknown fields |
| Frontend command cannot find package.json | The frontend is still a skeleton |
| Audit fails without a vulnerability report | Check advisory-service/network errors before interpreting the result |

Use the linked CI run when reporting a failed check. State the revision, command,
exit result, and whether the failure reproduced. Redact connection strings and tokens.
